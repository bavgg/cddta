HOW NETCUT SHOWS "ACTIVITIES" - THE KEY MECHANISM
================================================================

STEP 1: CONTINUOUS DEVICE DISCOVERY (LoopDevs)
-----------------------------------------------
while (true) {
    sendARPRequest(toEveryIPInSubnet);
    listenARPReplies();
    updateMAC_IP_Table();
    sleep(10);
}

Result: Always-current MAC↔IP mapping for every device.

STEP 2: TRAFFIC ATTRIBUTION (_processTraffic)
----------------------------------------------
// Runs on BPF/libpcap capture in promiscuous mode
for each captured packet {
    srcMAC = packet.ethernet.src;
    dstMAC = packet.ethernet.dst;

    // Map MAC to IP using ARP table
    srcIP = arpTable[srcMAC];
    dstIP = arpTable[dstMAC];

    // Count bandwidth per device
    deviceStats[srcIP].bytesSent += packet.length;
    deviceStats[dstIP].bytesRecv += packet.length;

    // Protocol classification
    if (packet.hasHTTP) {
        deviceStats[srcIP].webDomains.add(packet.httpHost);
        deviceStats[srcIP].httpRequests++;
    }
    if (packet.hasTLS) {
        deviceStats[srcIP].tlsDomains.add(packet.tlsSNI);
        deviceStats[srcIP].httpsConnections++;
    }
    if (packet.hasDNS) {
        deviceStats[srcIP].dnsQueries.add(packet.dnsQueryName);
    }
    if (packet.hasNetBIOS) {
        deviceStats[srcIP].hostname = packet.netbiosName;
    }
}

================================================================
THE CRITICAL DIFFERENCE: ARP SPOOFING FOR FULL VISIBILITY
================================================================

WITHOUT MITM (Passive Only - What You Can Do Safely):
------------------------------------------------------
- See ONLY your traffic + broadcast/multicast
- ARP mapping from your ARP table only
- No website visits for other devices
- No DNS queries from other devices

WITH MITM / ARP SPOOFING (What NetCut Does for "Cut" + "Monitor"):
--------------------------------------------------------------------
- ARP spoof target: "I am gateway" → target sends ALL traffic to NetCut
- ARP spoof gateway: "I am target" → gateway sends ALL traffic to NetCut
- NetCut forwards traffic (monitor) OR drops it (cut)
- Result: SEES EVERY PACKET FROM TARGET DEVICE
- Can show: Full browsing history, app usage, bandwidth by app

NetCut's "Cut" feature IS the ARP spoofing mechanism.
"Monitor" mode = ARP spoof + forward (full visibility)
"Cut" mode = ARP spoof + drop (denial of service)

KEY INSIGHT: THE "ACTIVITY VIEW" REQUIRES MITM
================================================================

NetCut's ability to show:
- "Website visits per device"
- "App usage per device"
- "Bandwidth by application per device"
- "Real-time traffic graphs per device"

ALL REQUIRE ARP SPOOFING (MITM) TO INTERCEPT OTHER DEVICES' TRAFFIC.

Without MITM, you only see:
- Your own traffic
- Broadcast/multicast (ARP, mDNS, DHCP, SSDP)
- Devices that talk directly to you

This is why NetCut's "Monitor" and "Cut" are the same underlying mechanism:
ARP spoofing enables BOTH traffic interception AND denial of service.

================================================================
CONCLUSION
================================================================

NetCut shows device activities by:
1. CONTINUOUS ARP SCANNING (LoopDevs) - knows every device
2. PASSIVE TRAFFIC CAPTURE (BPF/_processTraffic) - sees packets
3. MAC→IP ATTRIBUTION - maps every packet to a device
4. PROTOCOL CLASSIFICATION - identifies apps/domains/protocols
5. OPTIONAL ARP SPOOFING (MITM) - sees OTHER devices' traffic

The "secret sauce" for activity visibility is #5: ARP SPOOFING.
Without it, you only get device discovery, not activity monitoring.

For legitimate network monitoring: USE ntopng (passive, no MITM).
For learning MITM: USE ISOLATED LAB (VirtualBox host-only network).
