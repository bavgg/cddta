PHASE 3: TRAFFIC ATTRIBUTION (Uses the Map)
================================================================

COMMAND 3.1: Start Capture FIRST (Critical for SNI)
----------------------------------------------------
sudo tcpdump -i en0 -n -w /tmp/workflow_capture.pcap 2>/dev/null &
PID=$!
sleep 15
kill $PID 2>/dev/null

NOTE: Capture MUST start BEFORE connections to catch TLS Client Hello with SNI

COMMAND 3.2: TLS SNI Attribution (Websites/Apps)
-------------------------------------------------
tshark -r /tmp/workflow_capture.pcap -Y "tls.handshake.extensions_server_name" -T fields -e ip.src -e tls.handshake.extensions_server_name 2>/dev/null | \
awk -F'\t' 'NR==FNR{dev[$1]=$3; next} {name=dev[$1]; if(!name) name="UNKNOWN"; print "  " name " (" $1 ") → " $2}' /tmp/device_map_workflow.txt - | sort | uniq -c | sort -rn

RESULT: (No SNI captured in this 15s window - no new TLS handshakes)

COMMAND 3.3: DNS Query Attribution
-----------------------------------
tshark -r /tmp/workflow_capture.pcap -Y "dns" -T fields -e ip.src -e dns.qry.name 2>/dev/null | \
awk -F'\t' 'NR==FNR{dev[$1]=$3; next} {name=dev[$1]; if(!name) name="UNKNOWN"; print "  " name " (" $1 ") → " $2}' /tmp/device_map_workflow.txt - | sort | uniq -c | sort -rn

KEY INSIGHTS FROM THIS WORKFLOW
================================================================

1. DISCOVERY IS THE FOUNDATION
   - Without device map, attribution shows only IPs
   - "192.168.0.101 → apple.com" vs "iPhone → apple.com"

2. MULTI-LAYER DISCOVERY NEEDED
   - ARP alone: 1 device (router only)
   - TCP SYN: 7 devices (wakes sleepers)
   - Broadcast ping: Confirms .101, .102 alive
   - Service scan: Fingerprints type (Apple, OPPO)

3. ATTRIBUTION NEEDS TIMELY CAPTURE
   - Must capture BEFORE TLS handshake for SNI
   - 15s window may miss handshakes if no new connections
   - Continuous capture better for ongoing monitoring

4. MAC RANDOMIZATION IS NORMAL
   - 5e:, 96:, 0e:, c2:, ba:, 7e: prefixes = locally administered
   - Vendor lookup fails → need service fingerprinting
   - Port 62078 = definitive Apple despite random MAC

5. FIREWALLS HIDE PORTS
   - OPPO (.105) shows "filtered" not "closed"
   - Means firewall present, device alive

# --- DISCOVERY ---
ifconfig en0
sudo arp-scan --localnet --interface=en0
sudo nmap -sn -PS80,443,22,23,21 192.168.0.0/24
ping -c 3 192.168.0.255
sudo arp-scan --localnet --interface=en0
sudo nmap -sT -sV -p 49152,62078,5000,7000,46888,10152 192.168.0.101
sudo nmap -sT -sV -p 49152,62078,5000,7000,46888,10152 192.168.0.105
sudo nmap -sU -p 137,5353 192.168.0.101 192.168.0.105

# --- BUILD MAP ---
cat > /tmp/device_map.txt << 'EOF'
192.168.0.1	28:ee:52:f7:74:dc	TP-Link Router

192.168.0.101	96:2d:fc:a5:07:ff	iPhone
192.168.0.105	0e:70:b3:1a:68:38	OPPO Phone
EOF

# --- ATTRIBUTION ---
sudo tcpdump -i en0 -n -w /tmp/capture.pcap 2>/dev/null &
PID=$!
sleep 30
kill $PID 2>/dev/null

# SNI
tshark -r /tmp/capture.pcap -Y "tls.handshake.extensions_server_name" -T fields -e ip.src -e tls.handshake.extensions_server_name | \
awk -F'\t' 'NR==FNR{dev[$1]=$3; next} {name=dev[$1]; if(!name) name="UNKNOWN"; print name " (" $1 ") → " $2}' /tmp/device_map.txt - | sort | uniq -c | sort -rn

# DNS
tshark -r /tmp/capture.pcap -Y "dns" -T fields -e ip.src -e dns.qry.name | \
awk -F'\t' 'NR==FNR{dev[$1]=$3; next} {name=dev[$1]; if(!name) name="UNKNOWN"; print name " (" $1 ") → " $2}' /tmp/device_map.txt - | sort | uniq -c | sort -rn

# Bandwidth
tshark -r /tmp/capture.pcap -T fields -e ip.src -e frame.len | \
awk 'NR==FNR{dev[$1]=$3; next} {bytes[$1]+=$2} END {for(ip in bytes) {name=dev[ip]; if(!name) name="UNKNOWN"; mb=bytes[ip]/1024/1024; printf "%s (%s): %.2f MB\n", name, ip, mb}}' /tmp/device_map.txt - | sort -k4 -rn
